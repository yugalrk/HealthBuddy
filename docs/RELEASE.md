# Building and releasing HealthBuddy

## Toolchain

Everything lives under `$HOME` — no root was needed, and nothing was installed
system-wide:

| Tool | Location | Version |
|---|---|---|
| Flutter | `~/tools/flutter` | 3.47.4 stable (Dart 3.13.3) |
| JDK | `~/tools/jdk17` | Temurin 17.0.20.1+1 |
| Android SDK | `~/Android/Sdk` | platform 36, build-tools 36.0.0 |

`~/.bashrc` exports these (see the `HEALTHBUDDY_TOOLCHAIN` block), so a new
shell is ready to go. To verify:

```bash
flutter doctor -v      # Android toolchain should be ✓
```

"No devices available" is expected: this WSL2 environment has no USB
passthrough and no emulator.

## Day-to-day

```bash
flutter analyze                 # must be clean
flutter test                    # 37 tests, no device needed
dart run tool/demo_plan.dart 3  # print a sample week + shopping list
dart run tool/diagnose.dart     # why is a profile short on a nutrient?
dart run tool/bench.dart        # plan generation timing
python3 tool/make_icons.py      # regenerate icons and store graphics
```

## Previewing the UI without a device

```bash
flutter run -d web-server --web-port 8080
```

Then open `http://localhost:8080` in Windows Chrome — WSL2 forwards localhost.
This is for layout and flow only; always confirm real behaviour on a phone.

## Building for a phone

```bash
flutter build apk --debug        # sideload to test
```

Copy it somewhere Windows can reach, then install it on your phone:

```bash
cp build/app/outputs/flutter-apk/app-debug.apk /mnt/c/Users/<you>/Downloads/
```

## Release build for Play

### 1. Create the upload keystore (once, and never lose it)

Google signs your app with its own key, but your **upload key** is how you prove
a new build is really from you. If you lose it you must ask Google to reset it,
which takes days.

```bash
keytool -genkey -v \
  -keystore ~/healthbuddy-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload
```

Back that file up somewhere safe and private. It is deliberately **not** in the
repo and is covered by `.gitignore`.

### 2. Point Gradle at it

Create `android/key.properties` (also gitignored):

```properties
storePassword=<the password you just chose>
keyPassword=<the password you just chose>
keyAlias=upload
storeFile=/home/yugal/healthbuddy-upload.jks
```

### 3. Build the bundle

```bash
flutter build appbundle --release
# -> build/app/outputs/bundle/release/app-release.aab
```

Upload that `.aab` to the Play Console.

## Play Store requirements this project already meets

- **targetSdk 36.** Since 31 August 2026 Google Play rejects new apps below
  API 36. Flutter 3.47's default is 36, so `android/app/build.gradle.kts`
  inherits the right value.
- **No internet permission.** The manifest requests none, which makes the Data
  Safety form trivially honest: no data is collected because none can leave.
- **Privacy policy.** `store/PRIVACY_POLICY.md` — host it at a public URL
  (GitHub Pages is free) and paste that URL into the Play Console.
- **Graphics.** `store/play_icon_512.png` and
  `store/feature_graphic_1024x500.png`, both generated by `tool/make_icons.py`.
- **Listing copy.** `store/LISTING.md`.
